# TILESANDBOX — Game Brief

## 一句话

一个跑在浏览器与安卓上的 **2.5D 无缝大世界沙盒**：79200 × 12800 像素的连续世界由 16px tile 拼接而成，
玩家挖开地表、向下探索洞穴与矿脉、回到地面建造与耕种，并在昼夜与饥饿的压力下活下去。

## 平台与交付

| 端 | 形态 | 说明 |
|---|---|---|
| PC 浏览器 | 静态站点（GitHub Pages） | 键盘 + 鼠标，主力开发端 |
| 手机浏览器 | 同一套静态站点 | 触控（虚拟摇杆 + 点击挖掘）、竖屏/横屏适配 |
| 安卓 APK | Cordova 壳打包同一份 www | 由 GitHub Actions 构建产出 |

三端**同一份代码**（原生 ES modules，免打包构建），差异只在输入方式与性能档位。

## 核心玩法（三支柱）

1. **挖掘建造（骨架，必须先做）**
   - 世界由可破坏的 tile 组成，工具决定挖掘速度与可挖等级（硬度分层）。
   - 多层结构：地表 → 土层 → 岩石层 → 洞穴层 → 深层矿脉。
   - 放置与拆除方块建造据点；合成台把矿石变成材料与工具。
2. **生存探索（压力层）**
   - 昼夜循环：夜晚地表刷怪，光照是安全边界。
   - 饥饿与生命：进食回复，饥饿归零掉血。
   - 怪物与战斗：近战 + 远程，掉落材料。
3. **农场经营（经营层）**
   - 耕地种植、生长周期、季节/光照影响产出。
   - 围栏养殖、产出物收集。
   - 产出物进入合成与经济链，反哺探索与建造。

三支柱的关系：**挖掘建造提供空间与材料 → 生存提供压力与目标 → 农场提供稳定产出与长期经营**。

## 世界规格（硬约束）

| 项 | 值 |
|---|---|
| 世界像素 | 79200 × 12800 |
| tile 尺寸 | 16 px |
| tile 网格 | 4950 × 800（3,960,000 格） |
| 无缝 | 是，无加载门、无分区传送；左右与上下边界为世界硬边界 |
| 分块 | chunk = 64 × 64 tile（1024 × 1024 px）→ 78 × 13 = 1014 个 chunk |
| 生成 | 种子化程序化生成，按需生成 + 访问过才落盘（稀疏存储） |

## 技术栈

- 渲染：Canvas 2D（sprite + tile），**不上 WebGL/Three.js**（2.5D 用不上，且移动端兼容与体积更可控）。
- 语言：原生 JavaScript ES modules，无构建步骤。
- 存档：IndexedDB（浏览器）/ 同栈（APK 内 WebView 一样）。
- Tile 资产：`assets/data/tiles.json` 定义 tile 表；`Tiled`（.tsx/.tmx）用于**建筑模板与关卡片段**的编辑与导出，
  不作为 396 万格主世界的编辑格式。

## 首个垂直切片目标（M1）

在世界里**挖得动、放得下、走得动、看得见昼夜**：
1. 种子化生成一片 3 × 3 chunk 的可玩地表 + 一层洞穴。
2. 玩家可左右移动、跳跃、挖掘与放置 tile。
3. 摄像机跟随，视口只画可见 chunk。
4. 昼夜光照（白天/黄昏/夜晚三档渐变）。
5. 三端可跑：PC 键盘、手机虚拟摇杆、APK 内可运行。

## 非目标（M1 不做）

多人联机、模组系统、剧情任务、NPC 商店、天气系统、液体模拟、Boss 战。

## 风险

| 风险 | 缓解 |
|---|---|
| 396 万格世界内存与 GC 压力 | 稀疏 chunk + 只驻留视口周围 chunk，离场回收 |
| 移动端 Canvas 2D 逐格绘制慢 | 视口裁剪 + 脏矩形重绘 + 静态 chunk 预渲染到离屏 canvas 缓存 |
| 世界过大导致探索无目标 | 地表 POI（废墟/矿洞入口）+ 洞穴层矿脉引导向下 |
| 三端输入差异 | 输入抽象层：键盘 / 触控 / 手柄统一成 intent |
